gamekit2d · GitHub Actions 自动发布教程

一次配置，以后发版只需打一个 tag——编译、测试、打包、上传 PyPI 全自动

这套流程做什么：
  1. 你 push 代码 到 GitHub 仓库 yuleemoon/gamekit2d
  2. GitHub 免费开一台 Windows 虚拟机，装上 Python 3.13
  3. 自动执行：编译 C 扩展 → 跑 39 个单元测试 → 打 wheel + sdist → twine 校验
  4. 自动把 dist/ 里的包上传到 PyPI，全世界都能 pip install gamekit2d

1准备工作

  • GitHub 账号（已登录 yuleemoon/gamekit2d）
  • PyPI 账号（pypi.org）
  • 本地项目在 C:\Users\Administrator\Desktop\new-chat（已含 build_accel.py、pyproject.toml、tests/）
配置文件我已经帮你写好：.github/workflows/build.yml 和更新过的 .gitignore。你只需要执行命令。

2把项目推到 GitHub

在 C:\Users\Administrator\Desktop\new-chat 打开 PowerShell，依次执行：

# 1. 初始化 git（只做一次）
git init
git branch -M main

# 2. 提交所有文件
git add -A
git commit -m "gamekit2d 1.0.2: D3D11 fixed + GitHub Actions"

# 3. 关联你的 GitHub 仓库（只做一次）
git remote add origin https://github.com/yuleemoon/gamekit2d.git

# 4. 推上去（会提示输入 GitHub 账号密码或 Token）
git push -u origin main
如果仓库里已经有内容（比如 README），先执行 git pull origin main --allow-unrelated-histories 再 push。
GitHub 现在要求用 Personal Access Token 代替密码。不会生成的话：GitHub → Settings → Developer settings → Personal access tokens → Generate new token（勾选 repo 权限）。

3确认两个配置文件

3.1 .gitignore

保证 *.pyd / *.so / *.dll / dist/ / build/ 等编译产物和本地调试文件不会进仓库——CI 会在干净的机器上重新编译，仓库只存源码。

3.2 .github/workflows/build.yml

核心流程（每段干什么）：

# 触发条件：打 v 开头的 tag，或手动点 Run workflow
on:
  push:
    tags: ["v*"]
  workflow_dispatch:

jobs:
  build-windows:
    runs-on: windows-latest   # GitHub 免费提供的 Windows 虚拟机
    steps:
      - uses: actions/checkout@v4        # 把你的代码拷进虚拟机
      - uses: actions/setup-python@v5    # 装 Python 3.13
      - run: pip install build twine    # 装打包工具
      - run: python build_accel.py build_ext --inplace   # 编译 _accel/_d2d/_d3d11
      - run: python -m unittest discover -s tests -q     # 跑 39 个测试
      - run: python -m build            # 生成 wheel + sdist
      - run: python -m twine check dist/*   # 上传前自检
      - run: python -m twine upload dist/* --skip-existing   # 传到 PyPI
        env:
          TWINE_USERNAME: __token__
          TWINE_PASSWORD: ${{ secrets.PYPI_TOKEN }}

4PyPI 生成 API Token（一次）

1
登录 pypi.org → Account settings → API tokens，点 Add API token。
2
Scope 选 Entire account（或只勾 gamekit2d 项目），Token name 随便写，点创建。
3
复制生成的 pypi-xxxxxxxx 一串字符串。只显示一次，关掉就没了。
这个 token 就是你的 PyPI 密码，不要发到群里、贴进代码、commit 到仓库。

5把 Token 存进 GitHub Secret（一次）

1
打开 github.com/yuleemoon/gamekit2d → Settings
2
左侧 Secrets and variables → Actions → New repository secret
3
Name 填：PYPI_TOKEN　Value 粘贴第 4 步的 token → Add secret
名字必须和 workflow 里的 secrets.PYPI_TOKEN 完全一致，一个字母都不能差。

6发版：打 tag 触发自动发布

以后每次发新版，只需要三步：

# 1. 先改版本号（两个地方，保持一样）
#    pyproject.toml  →  version = "1.0.3"
#    gamekit/__init__.py  →  __version__ = "1.0.3"

# 2. 提交并打 tag（tag 名字 = v + 版本号）
git add -A
git commit -m "release 1.0.3"
git tag v1.0.3

# 3. 推送（tag 会触发 GitHub Actions）
git push origin main
git push origin v1.0.3

也可以手动触发：仓库页面 → Actions → 左侧 build-and-publish → Run workflow（不打 tag 也能构建，适合测试）。

7验证发布成功

  1. 仓库页面 → Actions → 看到 绿色 ✓ = 构建通过；点进去看每一步日志
  2. 打开 pypi.org/project/gamekit2d/，能看到新版本号
  3. 随便开个终端验证：pip install gamekit2d → python -c "import gamekit; print(gamekit.__version__)"

8常见问题 & 下一步

常见问题

现象原因 / 解决
上传报 400 Bad Request版本号已在 PyPI 存在。升版本号重新打 tag（PyPI 不允许覆盖同名版本）
报 403 ForbiddenSecret 没配对 / Token 过期。检查 Settings → Secrets → PYPI_TOKEN
编译步骤红叉点进日志看具体报错。C 代码改了要保证本地 build_accel.py build_ext --inplace 能过
Actions 没跑确认 push 的是 v* 开头的 tag，或手动 Run workflow

下一步：三平台全自动（Linux / macOS 后端写好之后）

在 build.yml 里复制一个 job 改成：

  build-linux:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install build twine
      - run: python build_accel.py build_ext --inplace
      - run: python -m unittest discover -s tests -q
      - run: python -m build
      - run: python -m twine check dist/*
      - run: python -m twine upload dist/* --skip-existing
        env:
          TWINE_USERNAME: __token__
          TWINE_PASSWORD: ${{ secrets.PYPI_TOKEN }}

macOS 把 ubuntu-latest 换成 macos-latest 即可。GitHub 会同时开三台机器，一次 push 出三个平台的 wheel。

注意：等 Linux/macOS 后端写好，还要把 wheel 标签改成平台专属（win_amd64 / manylinux / macosx），否则跨平台用户会装到不匹配的包。这个到时再一起改。
